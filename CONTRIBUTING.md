# Contributing

## Branches
Do not work directly on `main`.

Examples:
- `feature/23-create-product`
- `test/47-checkout-integration-tests`
- `fix/61-stock-race-condition`
- `docs/12-api-design`

## Commits
Keep commits logical and understandable:
- `feat(product): add product creation service`
- `test(product): add validation tests`
- `fix(checkout): prevent negative stock`
- `docs(api): document checkout errors`

## Pull Requests
A PR must:
- link the Issue,
- explain what changed,
- explain how it was tested,
- contain no secrets,
- pass CI,
- be reviewed by the other developer.

## Definition of Done
Implementation + appropriate tests + documentation update + partner review + passing CI.
