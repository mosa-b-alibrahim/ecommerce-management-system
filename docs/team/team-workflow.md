# Team Workflow

Both developers are developers and testers.

Avoid permanent split:
- Developer A = coding only
- Developer B = testing only

Instead rotate feature ownership. The feature owner writes implementation and appropriate tests; partner reviews both.

## Weekly rhythm
1. Sprint planning: choose only achievable Issues.
2. Shared learning for new concepts.
3. Each developer takes Issues.
4. Mid-week sync on blockers/interfaces.
5. PR review swap.
6. End-week integration/regression and retrospective.
